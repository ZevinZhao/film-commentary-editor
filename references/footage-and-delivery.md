# 素材核验、画面台账与交付

在寻找片源、建立逐句画面方案、审查成片或进行局部修订时读取。
目标是让每个剪辑决定有可用素材支持，并用实际导出证明任务已完成。

## 1. 先查资产，再确定制作范围

- 先检查用户给出的本地文件、当前工程与已下载素材，避免重复下载和重复分析。
- 将参考视频与待剪电影区分开：前者用于拆解节奏，不能冒充后者的剧情画面。
- 记录用户已经确认的时长、讲述范围、原声语言、画幅及版本，后续沿用。
- 用户授权寻找素材后，继续检索、核验及授权范围内的下载，不反复询问同一权限。
- 缺文件位置、付费购买或扩大任务范围确实需要用户决定时，才提出具体问题。
- 没有完整电影不等于完全不能做；先清点能够支撑的场景和因果链。
- 若素材只够一场戏，明确说明可做的片段长度和主题，不把它包装成完整主线。
- 用户坚持原定全片范围时，继续补足合法可得的缺口；实在不足时提供具体缺口与替代范围。
- 缩短文案、调整叙述边界或交付已约定的试剪，优于循环少数画面凑目标时长。
- 不擅自将完整解说任务改成预告片、静态幻灯片或另一部电影的画面拼贴。

## 2. 来源与访问条件分开记录

- 优先使用用户提供且可用于任务的本地素材，其次寻找可合法取得的可靠公开片段。
- 官方发行方、片方和可信授权频道通常有助于核实片名、版本及画面质量。
- “官方上传”证明来源身份；不自动证明用户已获再剪辑、转载或商业发布许可。
- 公开可看、技术上可下载、具有再利用依据是三件事，分别记录，不互相替代。
- 用户说“不商用”可说明用途，不能被写成对任意素材的版权授权。
- 只为当前解说取必要素材；不要把用户允许找短片解释成下载盗版完整电影的授权。
- 保留原始页面 URL、标题、上传者、访问日期、取得方式和对应本地文件。
- 区分已确认信息与上传者自称：例如标题写“4K”，实际下载可能只有 720p。
- 不知道具体再利用许可时写“未核实”，不要捏造“已授权”或提供自动合法的保证。
- 如任务涉及发布，沿用用户给定的使用边界；检索、制作与代为发布不是同一授权。

## 3. 下载失败的处理边界

- 先判断失败属于网络传输、失效公开链接、缺少音轨，还是明确的访问限制。
- 对超时、连接中断等传输问题，可有限重试、续传，或使用站点正常提供的另一格式。
- 对失效直链，可重新读取同一公开页面取得当前链接；不要猜测令牌或伪造权限。
- 工具本身需要网络权限时可走正常批准流程，这不增加对网站内容的访问权限。
- 遇到 DRM、付费墙、需要额外账户授权或明确的访问阻断，停止该访问路径。
- 不破解 DRM，不借用他人登录凭据，不使用绕过限制的代理或盗版来源补缺口。
- 同类错误连续重试且没有新信息时停止该方案；通常两三次足以判断是否需要换来源。
- 错误原因改变或有新的合法访问凭据时可重新判断，不把重试次数当成绝对技术规则。
- 保留失败状态、已完成文件和最后可恢复位置；不要因重试从头覆盖有效下载。
- 下载阻塞时继续做已有素材核验和剪辑方案，最后报告具体缺口，而非无限等待。

## 4. 下载完才开始验证可剪性

- 保存媒体探测结果：真实尺寸、显示比例、旋转信息、编码、帧率、时长及各音轨。
- 检查是恒定帧率还是可变帧率；源时码按时间戳解释，不只按帧号除以名义帧率。
- 检查音视频是否分别下载、是否成功合并；有画面并不代表有音轨。
- 核验实际选中的音轨，而非只信语言标签：英语原声、其他配音或混合旁白可能被错标。
- 在开头、转折和结尾听取人物说话，并结合转写、口型与场景判断版本。
- ASR 可辅助定位，不能单独证明没有对白、没有配音替换或听写完全正确。
- 外挂字幕通常表现为独立字幕流或旁挂文件；关闭或不复用该流即可去掉显示。
- 烧录字幕已经成为画面像素，没有字幕流也可能存在；必须实际看帧确认。
- 英语音轨可以同时带烧录日文字幕，两者并不矛盾，记录时不要混成一个“语言”字段。
- 用户要求净片时优先找真正干净的版本，不默认用大幅裁切遮字损失画面内容。
- 经用户接受的裁切或画幅调整也要检查主体、构图和输出比例，不假称原生净片。
- 横屏、竖屏、黑边与画面裁切均以实际像素核验；不要用横屏容器包装裁坏的竖屏。
- 接触表适合快速定位；关键动作和选定切点还需更密集取帧或播放附近片段。
- 对下载或合并存在疑点的文件做完整解码检查；不能只因文件存在就标记可用。
- 一次随机跳转的解码警告不等于全片损坏，结合全量解码和实际帧判断。

## 5. 素材清单的最小字段

```json
{
  "source_id": "scene_rooftop_clean",
  "local_path": "work/footage/scene_rooftop_clean.mp4",
  "source_url": "原始公开视频页面",
  "uploader": "页面核实的上传者",
  "source_identity": "official / nonofficial / user_supplied",
  "reuse_basis": "用户给定依据，或明确标为未核实",
  "media": {"width": 1920, "height": 1080, "fps": "24000/1001", "duration": 100.0},
  "audio": {"selected_stream": 1, "language_verified": "English", "verification": "试听与转写"},
  "subtitles": {"soft_tracks": [], "burned_in": "none_observed"},
  "verified_ranges": [{"in": 20.0, "out": 28.0, "content": "角色提出条件"}],
  "qa": {"decode_ok": true, "frame_proof": "对应接触表路径"}
}
```

这是字段示意，不是必须照搬的文件格式；只保留当前工作真正需要的字段。
`none_observed` 表示已检查范围内未见字幕，不将抽样结果夸大成逐帧保证。

## 6. 用 shot ledger 管理逐句画面

- 把每一句或紧密相连的两句叙述，映射到适合该含义的真实场景。
- “一句一个适合画面”是语义覆盖要求，不是强制每逢标点都切镜头。
- 连续动作可以覆盖两句；需要几个动作解释的一句也可以用多个镜头。
- 每行记录：段落与句子 ID、文案、来源 ID、源入点/出点、成片入点/出点及使用理由。
- 时间统一注明基准，例如各本地文件自身秒数，入点包含、出点不包含。
- 另存可微调范围与建议切点；不要让备用余量自动变成必须播满的时长。
- 画面理由写可观察事实，如“手松开衣领”，不要只写“紧张”“希望”“对应旁白”。
- 没有动作证据时可用同场反应作解释背景，但注明是概述，不声称画面证明了未出现的事。
- 不用入狱时的湿身镜头冒充多年后的遇袭，也不用角色任意张嘴画面假配另一段对白。
- 原声窗口单独锁定；同一镜头不要先铺旁白，又在紧接的原声里重复播放。
- 分工时共享源范围占用表，避免多人分别选中同一素材而直到合片才发现重复。
- 同一源文件的时间区间相交是直接重复；不同公开剪辑包含同场镜头是跨文件视觉重复。
- 两类重复分别检查，不能仅以文件名不同就宣称没有重复画面。
- 有意回看、对照或揭谜可以重用，但需说明叙事用途，并让观众理解这是回看。
- 小于一帧的取整交叠和不同角度的同场反应，不应夸大成循环凑时长。
- 候选素材太短时，先减少无画面支撑的复述，不随机延长、冻结或倒回已用镜头。

## 7. 换源与截点核验

- 同场景不同上传版本可能有删句、变速或片头，不能直接继承旧文件时码。
- 先找同一句话或同一个明显动作，再核对前、中、后三处是否保持一致偏移。
- 波形相关、画面匹配和字幕可辅助校时；单一锚点只支持局部映射。
- 若偏移随时间变化，分段映射或重新定位，不把可变关系硬套成一个常数。
- 每个原声窗确认字头、词尾、对方反应及下一句起点，给完整语意留出空间。
- 检查切入是否残留上一句半个词，切出是否吞掉话尾或提前显示字幕结论。
- 画面可以先切，原音尾可以后结束；保留的风声、脚步、呼吸也属于场景连续性。
- 原片旁白不能冒充纯配乐。延续尾声时确认下一英语对白尚未开始或已被妥善处理。

## 8. 检查实际导出的成片

- 检查最终文件存在、非零且可打开；工程文件、计划 JSON 和成功日志都不能代替成片。
- 从最终文件重新读取视频与音频时长、尺寸、帧率、轨道、起始时间及编码信息。
- 核对音视频末尾是否对齐，不能让播放器因较长音轨出现黑屏，或截断最后一个字。
- 对最终文件做解码检查，并检查开头、结尾、所有原声交接和用户点名修改处。
- 字幕依据实际最终音频校准；换配音、补停顿或替换句尾后重新核对相关字幕。
- 检查字头不要抢先、字尾不要拖进下一人发言；完整问答应按真实轮次显示。
- 字幕是否越界、遮脸、硬字幕叠字或在静默时残留，以最终输出画面为准。
- 黑帧检测先排除电影原有淡黑、黑边及有意停顿；不要把阈值告警直接当成故障。
- 冻结检测先排除静止镜头、几乎不动的反应和暗景；通过邻帧、时长与声音复核。
- 低差异帧不自动等于卡帧；真正的冻结或循环需定位成片时码与对应源区间。
- 重复审查结合 ledger 与实际画面，区分有意回看、自然相似构图和无意义复用。
- 原声是否听得见以成片实测和试听为准；有音轨或账面上留了几秒不等于对白成立。
- 同时检查中文旁白有没有盖住关键原声，以及原声后配乐、风声是否突然落到零。
- 只对本次变更和仍存疑处加深检查；没有新问题时不要反复重跑全部验证拖延交付。

## 9. 仅音频修改与最终交付

- 用户仅要求音频修订时，锁定视频、镜头顺序、画幅及已经认可的字幕画面。
- 优先复制原视频压缩码流，只替换音轨；不要顺手重剪、重配字幕或重新缩放。
- 比较修改前后的抽出视频码流哈希；整个 MP4 的哈希会因音轨和封装变化而改变。
- 如确需重新编码，说明原因并核对帧数、顺序、时间戳和关键画面；有损重编码通常会改变像素，不把近似画面说成解码帧哈希一致。
- 复测新音轨时长、峰值、对白电平、接点和片尾；图像哈希一致不代表音频已正确。
- 未验证到的内容明确列为限制，不说“完全一致”“全部检查通过”。
- 最终交付当前成片的可打开路径，并简述做了什么、检查了什么及尚存的实际限制。
- 用户需要可继续编辑时，再附字幕、素材清单和剪辑台账；不让一堆临时文件淹没成片。
- 保留被替换的有效版本及可追溯源文件，清理临时文件时不要删除后续修订所需资产。
